# 참도시농부(시흥시 텃밭 분양 서비스) — 시연용 프로토타입

**참도시농부**는 시흥시 관내 공공·민간·개인 텃밭을 등록하고, 시흥시민이 **추첨**으로 분양받으며, 텃밭지원과(가칭)가 검수·심의 상정·추첨·회수를 운영하고, **도시농업위원회**가 텃밭 지정을 심의하는 모바일 우선 웹앱입니다. 시흥시 AI 챌린지 대회 제출용이며, 처음 열었을 때 바로 시연할 수 있도록 가상 데이터를 담고 있습니다.

> ⚠️ 이 앱의 모든 사람 이름·전화번호·계좌·텃밭 이름은 **가상 데이터**입니다. 데이터는 이 브라우저의 `localStorage`에만 저장되고 서버로 전송되지 않습니다. 부서명 “텃밭지원과”는 **가칭**입니다.

## 실행 방법

Node.js 20 이상이 필요합니다. (Node 24에서 확인)

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm run build      # 타입 검사 + 정적 빌드 → dist/
npm run preview    # 빌드 결과 미리보기
npm test           # 단위·통합 테스트
```

**배포 주소: https://utggo00-del.github.io/Urban-Green-Thumb/** — `main` 브랜치에 푸시하면 GitHub Actions([.github/workflows/deploy.yml](.github/workflows/deploy.yml))가 테스트와 빌드를 거쳐 GitHub Pages에 자동 배포합니다.

`npm run build`로 만든 `dist/`는 GitHub Pages·Netlify·Vercel 같은 정적 호스팅에 그대로 올릴 수 있습니다. (`HashRouter`와 상대 경로 `base: './'`를 써서 새로고침·하위 경로 배포에도 깨지지 않습니다.)

## 시연 순서 (심사위원용)

화면 맨 위 **시연 바**에서 로그인 없이 역할을 바꿉니다. **시연 가이드** 버튼을 누르면 아래 5단계가 버튼 하나로 이동되는 안내로 나옵니다. 처음 상태로 돌아가려면 **데이터 초기화**를 누르세요.

| 단계 | 역할 | 할 일 | 볼 것 |
|---|---|---|---|
| 1 | 시민 | 텃밭 찾기 → 상세 → **3곳 지망 신청** | 지정 텃밭 12곳만 노출, “위원회 심의 완료” 배지, 신청 후 진행 단계 |
| 2 | 텃밭 제공자 | **내 땅 텃밭 등록 신청** (서류는 “시연용 샘플 서류 첨부”) | 소유자 동의서 필수, `검수중` 상태와 다음 회의 D-day |
| 3 | 관리자(간사) → 심의위원 → 관리자 | 실무 검수 → **안건 상정** → 출석 체크·**투표** → **의결** | “6명만 출석”이면 개회 불가, 가결 후 시민 화면에 공개, 의결 후 수정 잠금 |
| 4 | 관리자 | 마감 텃밭 **추첨 실행** → 결과 확인 → 확정·발표 → 감사 로그 | 시드값·실행 기록, 시민의 수락·포기, “기한 경과 시뮬레이션”으로 대기자 승계 |
| 5 | 관리자 | 경고 2회 이용자에게 **3번째 경고** → **회수 확정** → 대기자 승계 | 사유 필수, 회수 대상 배너, 새 이용자는 경고 0회로 시작 |

그 밖에 볼 만한 것: **텃밭 추천 도우미**(시민, AI 모의), **통계와 인사이트 요약**(관리자), **대리 신청 입력**, **공지·알림 관리**, **근거 조례** 페이지.

## 역할과 화면

| 역할 | 주요 화면 |
|---|---|
| 시민 | 홈, 텃밭 찾기(지도·목록·필터), 텃밭 상세, 분양 신청(4단계), 내 신청, 내 텃밭(경고·이용료 안내), 텃밭 등록 신청, 추천 도우미, 공지 |
| 텃밭 제공자 | 시민과 같은 메뉴(한 계정이 겸용). 내 등록 목록에서 검수·심의 진행과 부결·보류 사유 확인 |
| 관리자(간사) | 대시보드, 등록 실무 검수, 위원회 관리(회의·안건·의결·이관), 모집 관리, 추첨·감사 로그, 분양·이용자, 경고·회수, 공지·알림, 통계, 대리 신청 |
| 심의위원 | 안건 목록, 출석 체크, 안건 상세(소유자 이름 마스킹), 찬성·반대·보류 투표 |

역할에 맞지 않는 주소로 들어가면 “접근 권한 없음”이 나옵니다. (예: 심의위원은 추첨·경고·이용자 개인정보 화면에 접근할 수 없음)

## 근거 조례와 정책 설정값

근거: 「시흥시 도시농업 활성화 지원 조례」(시행 2025. 10. 2., 조례 제2528호). 조례 원문(국가법령정보센터 PDF)을 읽고 조문 요약을 만들었습니다. **도시텃밭 지정은 위원회 심의를 거칩니다**(제5조, 제11조). 위원회는 상·하반기 정례회의 연 2회와 임시회의, **재적 과반 출석 개회·출석 과반 찬성 의결**(제8조)로 운영합니다. 앱 안의 “근거 조례” 페이지에서 조문과 앱 기능의 연결을 볼 수 있습니다.

조례에 **규정이 없는** 정책은 제17조(“시행에 필요한 사항은 규칙으로 정한다”)에 따라 시행규칙·운영지침으로 정해야 하는 사항입니다. 이 앱은 대회 출품용 기획이므로 모두 **설정값**으로 분리했고([src/config.ts](src/config.ts)의 `DEFAULT_POLICY`), **실제 도입 시 시행규칙 확인이 필요합니다.**

| 정책 | 기본값 | 비고 |
|---|---|---|
| 신청 자격 | 시흥시민만 | `residentOnly` |
| 분양 방식 | 추첨제, 지망 최대 3곳 | `maxChoices` |
| 우선 배정 몫 | 전체 구획의 30% (다자녀·취약계층·노인) | `priorityQuotaRatio`, 모집별로 관리자가 변경. **확률 가중치는 없음** |
| 당첨 수락 기한 | 5일 | `acceptDeadlineDays` |
| 미경작 회수 | 경고 3회 누적 | `warningLimit` |
| 모집 주기 | 연 2회 (봄 2~3월, 가을 8~9월) | `seasonWindows` |
| 민간·개인 이용료 | 당첨자가 제공자 계좌로 직접 송금, 앱은 표시만 | 결제·정산 기능 없음 |
| 공공 텃밭 이용료 | 10,000원(가상 금액) | `publicGardenFee` |
| 위원회 정족수 | 재적 과반 출석·출석 과반 찬성 | 코드 상수 `COMMITTEE_RULES` |

SPEC에 없어서 **제가 정한 가정**도 모두 설정값이거나 코드에 근거를 적어 두었습니다.

| 가정 | 위치 |
|---|---|
| 우선 몫 좌석은 구획 수 × 비율을 **올림** (작은 텃밭도 0석이 되지 않게) | `lib/draw.ts` |
| 우선 몫에서 떨어진 분도 **일반 추첨에 다시 참여** (그렇지 않으면 우선 대상자가 일반 신청자보다 불리해짐) | `lib/draw.ts` |
| 지망이 얽힌 텃밭은 한 **묶음**으로 보고, 묶음 전체가 마감돼야 추첨 (일부만 추첨하면 모집 중인 다른 지망 신청자가 불공평) | `lib/recruitment.ts` |
| 끝까지 배정받지 못한 분은 지망 텃밭마다 대기번호, **대기 인원 상한** 초과는 낙첨 | `waitlistRatio` |
| 우선 배정 자기신고는 **관리자 확인 후** 우선 몫에 들어감 | `requirePriorityVerification` |
| 이용 기간 8개월 (수락일부터) | `usageTermMonths` |
| 신청 취소는 모집 마감 전까지만 (추첨 대상 확정 후 명단 변경 방지) | `lib/application.ts` |

조례가 다루지만 이번 프로토타입에서 **하지 않는 것**: 실결제·정산, 실제 본인인증·주민등록 연계, 실제 문자·알림톡 발송, 서버·DB 운영, 커뮤니티·재배 일지, 보조금(제15조), 교육훈련(제13조), 위원 위촉·해촉·수당(제4조, 제7조, 제10조).

## AI 기능 (규칙 기반 모의)

- **텃밭 추천 도우미**: 사는 동·이동수단·경험·관심 작물을 입력하면 조건에 맞는 텃밭(거리·시설·이용료·경쟁 정도로 점수화)과 이번 시즌 추천 작물을 안내합니다.
- **관리자 인사이트 요약**: 신청·배정·심의 데이터를 읽어 “대야동에는 지정 텃밭이 없어요”, “경쟁이 가장 치열한 텃밭” 같은 문장으로 알려 줍니다.

두 기능 모두 **API 키 없이 동작하는 규칙 기반 모의 AI**이고, 화면에 그렇게 표시합니다. 모든 답변 아래에는 “AI가 제공하는 참고 정보이며 정확한 내용은 텃밭지원과에 문의” 문구를 붙였습니다.

실제 AI 모델로 바꾸려면 `AiProvider`([src/lib/ai/provider.ts](src/lib/ai/provider.ts))를 구현해 `getAiProvider()`에서 `withFallback(실제공급자)`로 돌려주면 됩니다. 호출이 실패하면 자동으로 모의 답변으로 대체되고 화면에 그 사실이 표시됩니다. **주의: 이 앱은 정적 프런트엔드라 API 키를 코드에 넣으면 배포본에 노출됩니다. 키는 서버에 두고 서버(프록시)를 거쳐 호출하세요.**

## 기술 구조

React + TypeScript + Vite + Tailwind CSS(v4), 지도는 Leaflet + OpenStreetMap(API 키 불필요, 실서비스에서는 카카오맵으로 교체 예정), 차트는 순수 HTML/SVG.

```
src/
  types.ts            데이터 모델 (Garden, Recruitment, Application, Meeting, Agenda …)
  config.ts           정책 설정값, 시연 역할·계정, 시연 가이드
  data/
    repository.ts     ★ 데이터 접근 계층 — localStorage는 여기서만 만진다
    seed.ts           가상 시드 데이터 (고정 시드 → 초기화해도 항상 같음)
    selectors.ts      조회 도우미
  lib/                ★ 순수 로직 (화면·저장소를 모름)
    draw.ts           추첨 (우선 몫·지망·전원 배정·대기번호, 시드 기반 재현)
    committee.ts      위원회 개회·가결 판정
    warnings.ts       경고·회수
    allocation.ts     추첨 실행·확정, 수락·포기·승계, 기한 경과
    recruitment.ts    모집 개설·상태, 추첨 묶음
    workflow.ts       등록 → 검수 → 심의 → 지정 상태 전이
    stats.ts / notices.ts / application.ts / registration.ts / ai/
  components/         공용 부품 (레이아웃, 차트, 폼 …)
  pages/              citizen · admin · committee · ordinance
```

- **데이터 계층 분리**: 화면은 `repository`(`getSnapshot`·`subscribe`·`update`·`reset`)만 사용합니다. 나중에 API 클라이언트로 바꿔 끼울 수 있습니다.
- **재현 가능한 추첨**: 시드 기반 난수(mulberry32)를 쓰므로 같은 시드·같은 신청이면 결과가 같고, 시드값은 감사 로그에 남습니다.
- **테스트**: `npm test`. 추첨(우선 그룹·지망·전원 배정·대기번호, 확률 동등성, 무작위 시나리오 불변식), 위원회 정족수 경계값(짝수·홀수 인원), 경고·회수(3회), 등록·심의 전체 경로, 승계, 통계, 공지, 대리 신청, AI 추천·폴백까지 검증합니다.

## 접근성·디자인

- 고령자 친화: 본문 16px 이상, 보조 문구 15px, 주요 버튼 최소 높이 48px, 한 화면에 하나의 핵심 행동(신청은 4단계 마법사).
- 시맨틱 HTML, 키보드 이동·포커스 표시, 건너뛰기 링크, 다이얼로그는 네이티브 `<dialog>`.
- 상태는 색만으로 구분하지 않고 아이콘·글자를 함께 씁니다. 글자·배경 조합은 대비 4.5:1 이상으로 확인했고, 본문 속 링크는 항상 밑줄을 둡니다.
- 차트는 검증된 팔레트를 쓰고 모든 차트에 “표로 보기”를 제공합니다.
- 자동 점검: [axe-core](https://github.com/dequelabs/axe-core)(WCAG 2.1 A/AA)로 시민·관리자·심의위원의 주요 화면과 상태를 검사해 위반 0건을 확인했습니다. 360px 폭과 데스크톱에서 가로 넘침이 없습니다.
- 빈 상태·오류 상태·로딩 상태를 모두 두었습니다. 화면에서 예기치 않은 오류가 나도 앱 전체가 멈추지 않고 “시연 데이터 초기화” 출구를 보여 줍니다.

## 알려진 한계

- 시연 기준일은 2026.09.20로 고정되어 있고 “기한 경과 시뮬레이션”으로만 앞으로 갑니다. (어느 날짜에 열어도 D-day가 같게 보이도록)
- 한 브라우저 안의 데이터이므로 여러 사람이 동시에 쓰는 상황(동시 수정)은 다루지 않습니다.
- 위원장·부위원장이 모두 없을 때 위원장이 지명한 위원이 직무를 대행하는 규정(조례 제6조 제2항 후단)은 표시하지 않습니다.
